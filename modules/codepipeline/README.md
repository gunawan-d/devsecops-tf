# AWS CodePipeline Module

Creates a complete CI/CD pipeline: Source (GitHub) → Build (CodeBuild) → Deploy (ECS).

![CodePipeline Architecture](./image.png)

## 🏗️ Resources Created

- **`aws_s3_bucket.codepipeline_bucket`** - S3 bucket for pipeline artifacts with versioning and SSE-KMS encryption
- **`aws_iam_role.codepipeline_role`** - IAM role for CodePipeline with least-privilege permissions
- **`aws_iam_role_policy.codepipeline_policy`** - Scoped IAM policy attached to pipeline role
- **`aws_codepipeline.codepipeline`** - The pipeline with Source, Build, and Deploy stages

## 📥 Input Variables

| Name | Type | Required | Default | Description |
|------|------|----------|---------|-------------|
| `project_name` | `string` | Yes | - | Name of the project (used for naming resources) |
| `github_oauth_token` | `string` | Yes | - | GitHub personal access token (PAT) with repo access (sensitive) |
| `github_repository` | `string` | No | `"gunawan-d/apps-tf"` | GitHub repository in format "owner/repository" |
| `github_branch` | `string` | No | `"main"` | GitHub branch to trigger pipeline from |
| `codebuild_project_name` | `string` | Yes | - | Name of the CodeBuild project to use (output from codebuild module) |
| `ecs_cluster_name` | `string` | Yes | - | ECS cluster name to deploy to |
| `ecs_service_name` | `string` | Yes | - | ECS service name to update |
| `tags` | `map(string)` | No | `{}` | Tags to apply to all resources |

## 🔗 Outputs

| Name | Description |
|------|-------------|
| `codepipeline_id` | CodePipeline ID |
| `codepipeline_name` | CodePipeline name |
| `s3_bucket_name` | S3 bucket name for artifacts |

## 💡 Usage Example

```hcl
module "codebuild" {
  source = "./modules/codebuild"
  project_name       = "myapp"
  image_repo_name    = "myapp-repo"
  image_tag          = "latest"
  # ... other codebuild variables
}

module "codepipeline" {
  source                 = "./modules/codepipeline"
  project_name           = "myapp"
  github_oauth_token     = var.github_oauth_token  # Set via env var
  github_repository      = "myorg/myapp"
  github_branch          = "main"
  codebuild_project_name = module.codebuild.codebuild_project_name
  ecs_cluster_name       = module.ecs.ecs_cluster_name
  ecs_service_name       = module.ecs.ecs_service_name
}
```

## 🔐 Security & IAM Permissions

This module implements **least-privilege** IAM policies:

- **S3**: Scoped to pipeline's bucket only (read/write artifacts)
- **CodeBuild**: Scoped to specific project ARN
- **ECS**: Scoped to specific cluster and service (describe, update, register task definition)
- **IAM PassRole**: Required for ECS task role; may use wildcard if exact role unknown

**Important**: The `iam:PassRole` action uses `Resource = "*"` because the exact task execution role ARN may not be known at plan time. For production, consider scoping this to the specific ECS task execution role ARN.

## 🔄 Pipeline Flow

```
GitHub Push → CodePipeline Source → CodeBuild → ECS Deploy
```

1. **Source**: Fetches source from GitHub using OAuth token
2. **Build**: Triggers CodeBuild project (builds Docker image, pushes to ECR, outputs imagedefinitions.json)
3. **Deploy**: ECS action reads imagedefinitions.json, registers new task definition, updates service

## 🗂️ Integration with CodeBuild

The pipeline expects CodeBuild to produce an `imagedefinitions.json` artifact:

```json
[
  {
    "name": "app-container",
    "imageUri": "123456789012.dkr.ecr.us-east-1.amazonaws.com/myapp:latest"
  }
]
```

This file is automatically generated by the `buildspec.yml` provided in the root of this repository.

## ⚙️ GitHub OAuth Token Setup

**Never hardcode the token.** Use environment variable:

```bash
export TF_VAR_github_oauth_token="ghp_xxxxxxxxxxxxxxxxxxxxxxxxxxxx"
```

Create a GitHub PAT with `repo` scope.

## 🚀 Applying This Module

Apply after VPC, Security Groups, ALB, ECS, and CodeBuild modules:

```bash
terraform apply -target=module.vpc
terraform apply -target=module.sg
terraform apply -target=module.alb
terraform apply -target=module.ecs
terraform apply -target=module.codebuild
terraform apply -target=module.codepipeline
```

Or apply all at once (dependencies will be respected):

```bash
terraform apply
```

## 🧹 Cleanup

```bash
terraform destroy -target=module.codepipeline
terraform destroy -target=module.codebuild
# Then destroy other modules in reverse order
```

**Order matters:** Delete pipeline first, then build project, then other resources.

## 🔗 Dependencies

This module depends on:
- `modules/codebuild` (provides `codebuild_project_name`)
- `modules/ecs` (provides cluster and service names)
- `modules/vpc`, `modules/security_group`, `modules/alb` (network infrastructure)

**Apply order:** VPC → SG → ALB → ECS → CodeBuild → CodePipeline

## 📝 Notes

- S3 bucket has `force_destroy = true` for easy cleanup
- Pipeline uses GitHub as source; for AWS CodeCommit, change provider
- Buildspec path defaults to `buildspec.yml` in repository root
- Region and Account ID are automatically detected via data sources (no need to pass variables)
